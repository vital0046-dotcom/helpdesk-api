# Показ преподавателю за 5 минут

## Открыть проект

На компьютере Виталия есть ярлык на рабочем столе **Helpdesk — показать проект**.
Можно также открыть **Показать проект.cmd** в папке проекта. Оставь выбранным
режим **Локально · SQLite · без интернета**. Сервер запускается автоматически.

В окне нажимай **Следующий шаг →**. Каждый щелчок выполняет очередной настоящий
HTTP-запрос. Вкладка **Отправленный запрос** показывает метод, адрес и JSON.
Вкладка **Ответ сервера** показывает реальный ответ, код и время выполнения.
Любой выполненный шаг можно выбрать в таблице и снова посмотреть его результат.

Кнопка **Пройти показ целиком (01–11)** выполняет демонстрацию автоматически
до статистики. Потом можно разбирать результаты по строкам. **Новый сценарий**
очищает историю в окне и начинает новый показ; ранее созданные записи сохраняются.

## Что говорить

«Я разработал REST API для службы технической поддержки на Python и Flask.
Данные хранятся в связанных таблицах: пользователи, категории, заявки и комментарии.
На хостинге используется PostgreSQL, здесь для демонстрации без интернета — SQLite.
Окно на экране — вспомогательный HTTP-клиент. Те же запросы есть в коллекции Postman».

1. **01–03.** «Проверяю соединение с API и базой. Создаю автора и категорию заявки.
   Сервер возвращает идентификаторы, клиент сохраняет их для следующих запросов».
2. **04.** «Создаю заявку. POST возвращает 201 и объект со статусом new».
3. **05.** «Фильтрую новые заявки высокого приоритета, использую пагинацию».
4. **06.** «Пробую закрыть новую заявку сразу. Сервер возвращает 409: правило
   требует сначала взять её в работу. Это ожидаемый ответ, проверка успешна».
5. **07–09.** «Перевожу заявку в in_progress, добавляю комментарий и читаю его».
6. **10–11.** «Закрываю обработанную заявку. Получаю общую статистику».
7. **12–14, по желанию.** «Удаляю записи текущего теста. DELETE возвращает 204
   без тела ответа; комментарии удаляются вместе с заявкой».

## Если спросят

**Почему API, а не сайт?** Задание посвящено серверной разработке, REST, базе данных,
тестам и деплою. Полноценный пользовательский веб-кабинет в эту версию не входит.

**Как защищён сервис?** На Render используется общий X-API-Key. В локальном окне
генерируется временный ключ. Индивидуальных паролей пользователей и ролей ещё нет.

**Почему две базы?** PostgreSQL используется при размещении на Render, SQLite —
для простого локального запуска. SQLAlchemy и миграции позволяют использовать обе.
Локальные и облачные записи различаются и не синхронизируются.

**Зачем отдельное окно?** Оно помогает показать HTTP-запросы без ручного ввода
ключей и идентификаторов. Бизнес-правила по-прежнему выполняет сервер Flask.

## Облачный режим

Адрес API: https://helpdesk-api-3kw3.onrender.com . Его проверка доступности — `/health`.
В окне можно выбрать **Render · PostgreSQL · интернет**. Для этого нужен локальный
файл `.env.render` с API_KEY; он уже подготовлен на компьютере Виталия и не публикуется.
Бесплатный Render останавливает сервис после простоя, а текущая проверка внешнего
доступа завершилась тайм-аутом. Для защиты используй проверенный локальный режим,
пока облачное соединение не восстановлено.
