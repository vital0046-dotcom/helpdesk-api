# Контракт API

Базовый адрес локально: `http://127.0.0.1:8000`. Тела POST/PATCH — JSON-объекты,
заголовок `Content-Type: application/json`. При заданном API_KEY каждый `/api/*`
запрос требует заголовок `X-API-Key`. `/` и `/health` доступны без ключа.
OPTIONS разрешён для CORS preflight; по умолчанию сторонние origins не разрешены.
`CORS_ORIGINS` задаётся списком точных адресов через запятую; CORS не заменяет авторизацию.

| Метод | Путь | Назначение |
|---|---|---|
| GET, POST | /api/users | Список и создание автора |
| GET, PATCH, DELETE | /api/users/{id} | Чтение, изменение, удаление автора |
| GET, POST | /api/categories | Список и создание категории |
| GET, PATCH, DELETE | /api/categories/{id} | Чтение, изменение, удаление категории |
| GET, POST | /api/tickets | Список и создание заявки |
| GET, PATCH, DELETE | /api/tickets/{id} | Чтение, изменение, удаление заявки |
| GET, POST | /api/tickets/{id}/comments | Комментарии заявки |
| PATCH, DELETE | /api/tickets/{id}/comments/{comment_id} | Изменение текста и удаление комментария этой заявки |
| GET | /api/stats | Статистика |
| GET | /health | Доступность подключения к БД |

## Поля

- Пользователь: `name` (1–100 символов), `email` (до 254, уникальный, приводится к нижнему регистру).
- Категория: `name` (1–80, уникальное).
- Заявка при создании: `title` (1–200), `description` (1–10000), `author_id`, `category_id` обязательны.
  `priority` необязателен: low/medium/high, по умолчанию medium. Начальный статус всегда new.
- PATCH заявки: title, description, category_id, priority, status. Автор после создания неизменяем.
- Комментарий: `text` (1–5000), `author_id`; заявка определяется адресом запроса.

Пустые строки, null, неизвестные поля и неверные внешние ключи отклоняются.
Переходы: `new -> in_progress -> closed`; повторное открытие `closed -> in_progress`.
Повторная установка текущего статуса разрешена; `new -> closed` возвращает 409.
Удаление заявки удаляет комментарии. Пользователь или категория с зависимыми записями не удаляются (409).

## Фильтрация и страницы

`GET /api/tickets?status=new&priority=high&category_id=1&author_id=1&q=printer&page=1&per_page=10`

Фильтры комбинируются через AND. q ищет подстроку в заголовке; `%` и `_` считаются обычными
символами. Регистронезависимость не-ASCII символов зависит от СУБД и её collation;
стандартная SQLite не обеспечивает полную регистронезависимость русского текста.
Порядок: created_at по убыванию, затем id по убыванию. page >= 1, per_page 1–100.
Пагинация поддержана и у списков пользователей, категорий и комментариев.

```json
{"items": [], "page": 1, "per_page": 10, "total": 0, "pages": 0}
```

## Ответы и ошибки

200 — успешное чтение/изменение; 201 — создание; 204 — удаление без тела;
400 — неверный JSON/поля/параметры; 401 — неверный ключ; 404 — нет записи;
405 — метод не разрешён; 409 — дубликат/связи/переход статуса;
413 — тело больше 64 КБ; 415 — неверный Content-Type; 503 — БД недоступна на /health.

```json
{"error": {"code": 400, "message": "title must contain 1..200 characters"}}
```

Даты ISO 8601 в UTC. Внутренние детали SQL и стек ошибок клиенту не передаются.
